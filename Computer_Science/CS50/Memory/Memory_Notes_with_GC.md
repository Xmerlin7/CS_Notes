
# 🧠 الذاكرة (Memory) في الحوسبة

الذاكرة هي المكوّن المسؤول عن تخزين البيانات والتعليمات المطلوبة لتشغيل البرامج. تنقسم لعدة أنواع حسب طبيعة استخدامها وسرعتها وعلاقتها بالمعالج.

---

## أولًا: أنواع الذاكرة من حيث موقعها ووظيفتها

### 1. **RAM** (الذاكرة العشوائية)
- ذاكرة مؤقتة ومتطايرة (تفقد البيانات عند انقطاع الكهرباء)
- تُستخدم لتخزين البيانات أثناء التشغيل

### 2. **ROM** (الذاكرة الثابتة)
- تحتوي على بيانات لا تتغير غالبًا
- مثال: BIOS

---

## ثانيًا: أنواع الذاكرة في وقت التشغيل (Runtime Memory)

### 🔸 Stack Memory
- تُستخدم لتخزين المتغيرات المؤقتة (local variables) داخل الدوال
- تُدار بشكل تلقائي (push/pop)
- سريعة جدًا
- يتم حذف محتواها تلقائيًا عند انتهاء تنفيذ الدالة

```c
void func() {
   int x = 5; // x في ال Stack
}
```

### 🔸 Heap Memory
- تُستخدم لتخزين البيانات التي نطلبها يدويًا أثناء التشغيل (dynamic memory)
- تحتاج إلى إدارة يدوية (malloc/free في C، أو garbage collection في بعض اللغات)
- أبطأ لكنها أكثر مرونة

```c
int* p = malloc(sizeof(int)); // حجز مكان في Heap
```

---

## الفرق بين Stack و Heap

| العنصر         | Stack                  | Heap                       |
|----------------|------------------------|----------------------------|
| السرعة         | أسرع جدًا              | أبطأ نسبيًا               |
| الإدارة        | تلقائي (نهاية الدالة)  | يدوي / Garbage Collection |
| الحجم           | صغير ومحدود           | كبير ومرن                 |
| الاستخدام       | متغيرات مؤقتة          | كائنات طويلة العمر        |

---

## ثالثًا: علاقة الذاكرة بالبرمجة

- كل متغير له **عنوان (Address)** في الذاكرة
- توجد أنواع بيانات (int, float, pointer…) تختلف في **عدد البايتات** التي تشغلها
- الـ Pointers تسمح لنا بالوصول إلى موقع الذاكرة مباشرة

```c
int x = 10;
int* p = &x; // p يحتوي عنوان x
```

---

## 🧹 Garbage Collector (GC)

بعض لغات البرمجة مثل Java, Python, JavaScript تحتوي على آلية **جمع النفايات** (Garbage Collection) والتي تُستخدم لإدارة الذاكرة تلقائيًا، خصوصًا في الـ Heap.

### آلية العمل:

- تتابع الـ GC الكائنات التي لم يعد البرنامج يستخدمها (غير مرتبطة بأي متغير).
- تقوم بتحرير تلك المساحات تلقائيًا بدون الحاجة لاستدعاء free أو delete.

### المزايا:
- تقليل أخطاء الذاكرة مثل Memory Leak
- تسهيل البرمجة وتقليل عبء الإدارة اليدوية

### العيوب:
- استهلاك جزء من الأداء في وقت التشغيل
- أحيانًا لا يكون التوقيت دقيقًا في جمع الكائنات غير المستخدمة

---

## مفاهيم إضافية

- **Memory Leak**: فقدان الوصول إلى بيانات في الـ Heap دون تحريرها → يؤدي إلى استهلاك الذاكرة
- **Segmentation Fault**: محاولة الوصول إلى مكان غير مصرح به في الذاكرة
- **Cache Memory**: ذاكرة صغيرة وسريعة بين المعالج و RAM لتحسين الأداء
