# 🧠 Hash Tables – فهم عميق لمطور الـ Full-Stack

## ما هي الهاش تيبل (Hash Table)؟
Array of linked lists
الهاش تيبل هي بنية بيانات (Data Structure) تُستخدم لتخزين البيانات في أزواج (مفتاح:قيمة – Key:Value) وتوفر وصولًا سريعًا للغاية للبيانات، غالبًا في الزمن O(1) في أفضل الحالات وتجمع بين سرعة البحث لل Array و سرعة الإضافة والحذف في ال Linked Lists. 

تعمل من خلال دالة تُسمى **دالة الهاش (Hash Function)** تقوم بتحويل المفتاح إلى موقع داخل مصفوفة داخلية تُخزن فيها القيم.

---

## لماذا تعتبر الهاش تيبل أساسية لمطور الـ Full-Stack؟

### 1. **البرمجة اليومية وفهم الأداء**
- تُستخدم في تنفيذ الخرائط (Maps) والقواميس (Dictionaries).
- مثالية لحل المشاكل التي تتطلب بحثًا سريعًا (مثل الـ lookup أو frequency count).

### 2. **في الـ Backend (Node.js, Django, etc.)**
- التخزين المؤقت **(Caching)**: تخزين البيانات مؤقتًا لتقليل استعلامات قواعد البيانات وهذا يوفر الضغط على السيرفر.
- أنظمة الجلسات (Sessions): تخزين بيانات الجلسات باستخدام مفاتيح.
- معالجة التوكنات (JWT, CSRF tokens): تخزين التوكنات بطريقة آمنة وسريعة.

### 3. **في الـ Frontend**
- تحسين أداء المكونات (Component Caching).
- استخدام `Map` و `Set` في JavaScript والتي تعتمد داخليًا على مفهوم الهاش تيبل.

### 4. **في التطبيقات الكبرى**
- **نظام أسماء النطاقات (DNS)**: تحويل أسماء النطاقات إلى عناوين IP.
- **إدارة الذاكرة**: كمرجع سريع في الـ Garbage Collector
  
  الـ **Garbage Collector (GC)** هو نظام داخل لغات البرمجة عالية المستوى مثل JavaScript وPython وJava، وظيفته إنه يتابع الأشياء (الكائنات – objects) اللي ماعدش ليها استخدام (unreachable) ويحرر الذاكرة اللي كانت محجوزة ليها تلقائيًا.

لكن كيف يحدد الـ GC إذا كان الكائن ده لسه "حي" أو "ميت"؟ هنا بييجي دور الـ **"المرجعية" أو الـ Reference Graph**.

### 🌐 فكرة المرجعية:

تخيل البرنامج زي شبكة من الكائنات (objects)، كل كائن ممكن يكون بيرجع لكائنات تانية (references).  
الـ GC بيبدأ من نقطة اسمها **"الجذور" – roots** (زي المتغيرات العالمية، stack variables)، ويمشي يتتبع كل الكائنات المرتبطة ببعض.

### 🧾 وده يتم باستخدام نوع من أنواع الـ Hash Tables:

1. **عند التتبع**، الـ GC بيستخدم بنية شبيهة بالهاش تيبل علشان يتذكر إيه الكائنات اللي زارها فعلًا.
    
2. بيتجنب إنه يزور نفس الكائن مرتين.
    
3. بيحدد مين فاضل متعلق بشيء (reachable)، ومين فُقد الاتصال بيه (unreachable) وبالتالي يتم مسحه من الذاكرة.
    

يعني باختصار:

> الهاش تيبل هنا بتُستخدم كوسيلة مساعدة سريعة للبحث والتتبع داخل خوارزمية الـ GC، عشان تقرر مين "عايش" ومين "لا".
- **خوارزميات التوصية، تحليل البيانات، البحث السريع.**

## أمثلة على استخدام الهاش تيبل

- كشف العناصر المكررة في مصفوفة.
- حساب تكرار الكلمات أو الحروف.
- التحقق من إذا كان هناك زوج مجموعهم عدد معين (two-sum).
- Cache نتائج دوال ثقيلة باستخدام memoization.

## مفاهيم يجب أن تتقنها:

## Hash Function (دالة التجزئة)

هي الدالة المسؤولة عن تحويل المفتاح (key) إلى موقع معين داخل مصفوفة (عادة تسمى الـ bucket array).  
هدفها الأساسي هو توزيع البيانات بالتساوي داخل المصفوفة لتقليل فرص التضارب.

### خصائص دالة التجزئة الجيدة:

- **Deterministic**: دائمًا ترجع نفس القيمة لنفس المفتاح.
    
- **سريعة جدًا في الحساب**.
    
- **تُنتج توزيعًا جيدًا** حتى مع مفاتيح متقاربة أو متشابهة.
    

### مثال مبسط:
```js
function hash(key, size) {
  let total = 0;
  for (let char of key) {
    total += char.charCodeAt(0);
  }
  return total % size; // يعيد موقع في المصفوفة
}
```

## 🔹 Collision Handling (التعامل مع التصادمات)

بما إن دالة التجزئة قد تُرجع نفس الموقع لأكثر من مفتاح، لازم يكون فيه آلية لحل **التصادمات (Collisions)**.

### 1. **Chaining (التسلسل):**

- كل موقع في المصفوفة يحتوي على **قائمة (Linked List أو Array)**.
    
- عند التصادم، تُضاف القيم الجديدة في نفس القائمة.
    

#### مثال:


`Index 2 → ["apple", "banana", "grape"]`

### 2. **Open Addressing (العنوان المفتوح):**

- عند التصادم، يتم البحث عن **موقع فارغ جديد** داخل المصفوفة نفسها بناءً على نمط معين (Linear probing, Quadratic probing, etc).
    
- كل موقع يحتوي عنصر واحد فقط.
#### مثال (Linear Probing):


`Index 2 → Occupied Index 3 → Check next Index 4 → Found empty → Store here`

## 🔹 Time & Space Complexity

|العملية|Hash Table (جيدة)|
|---|---|
|**Insertion**|O(1)|
|**Lookup (Get)**|O(1)|
|**Deletion**|O(1)|

> ⚠️ لكن في حالة التصادمات السيئة (أو دالة تجزئة رديئة)، ممكن تتدهور لـ O(n).

### بالنسبة للمساحة:

- تستخدم مصفوفة بحجم معين غالبًا أكبر من عدد العناصر لتقليل احتمالات التصادم.
    
- تعتمد الكفاءة على ما يسمى بـ **Load Factor**.
    

---

## 🔹 Dynamic Resizing (إعادة التحجيم الديناميكي)

مع تزايد عدد العناصر، بيزيد احتمال التصادمات، فبتحتاج الـ Hash Table **تُضاعف حجمها تلقائيًا**.

### كيف يحدث هذا؟

- عندما يتجاوز **Load Factor** (مثل 0.7)، يتم إنشاء **مصفوفة جديدة أكبر**.
    
- يتم **إعادة تجزئة كل العناصر** (Rehashing) إلى المصفوفة الجديدة.
    
- هذا يجعل العملية مكلفة مؤقتًا، لكنها تحافظ على الأداء العام في المتوسط.
    

#### Load Factor = `number of items / array size`

## 📌 ملخص سريع للمراجعة:

|العنصر|الوصف|
|---|---|
|**Hash Function**|تحوّل المفتاح إلى فهرس باستخدام خوارزمية سريعة|
|**Collision Handling**|طريقة التعامل مع المفتاحين في نفس الموقع (Chaining أو Open Addressing)|
|**Time Complexity**|O(1) في الأحوال الجيدة، O(n) في الأسوأ|
|**Dynamic Resizing**|عند امتلاء الجدول، يتم توسيعه وإعادة توزيع العناصر|

## 🧪 كود تطبيقي بسيط:

```js
class HashTable {
  constructor(size = 10) {
    this.data = new Array(size);
  }

  _hash(key) {
    let hash = 0;
    for (let i = 0; i < key.length; i++) {
      hash = (hash + key.charCodeAt(i) * i) % this.data.length;
    }
    return hash;
  }

  set(key, value) {
    const index = this._hash(key);
    if (!this.data[index]) this.data[index] = [];
    this.data[index].push([key, value]);
  }

  get(key) {
    const index = this._hash(key);
    const bucket = this.data[index];
    if (!bucket) return undefined;
    for (let [k, v] of bucket) {
      if (k === key) return v;
    }
  }
}

```
